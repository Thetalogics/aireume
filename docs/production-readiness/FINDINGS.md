# Production readiness findings

Baseline: [approved remediation design](../superpowers/specs/2026-10-21-production-readiness-ui-ux-remediation-design.md), 2026-10-21.

All 14 baseline findings start as `reproduced`, reflecting the verified baseline
in the design. Owners are unassigned until work is allocated. Empty closure
fields mean investigation or verification is outstanding; they are not waivers.
This initial ledger does not claim fixes or fresh reproduction of baseline defects.
Later rows record verification done after that seed. `focused verification` is not closure.

Lifecycle: `discovered` → `reproduced` → `test added` → `fixed` →
`focused verification` → `full verification` → `closed`.
The only alternative terminal state is `inapplicable`, requiring reproduction
steps and evidence explaining why. Deferred and suppressed states are invalid.

A closed finding requires root cause, files changed, regression tests or a
verification method, focused result, full-suite result, evidence, and residual
risk. Visual findings also require before/after screenshot references. For
release-blocking findings, residual risk must be `none known`; a nonempty risk
entry alone does not satisfy the release gate. Evidence must be reviewed for
correctness: structural validation cannot establish the truth of claims, check
external controls, or verify screenshot contents. Escape literal pipes in cells
as `\|`. Keep this as one findings table with one row per baseline ID; additions
to the agreed baseline require an explicit validator/schema update.

Validation API: `scripts.validate_findings.validate_findings(path: Path)` returns
a list of structural errors; `[]` means the ledger is structurally valid.
Run focused checks with `python -m pytest tests/test_validate_findings.py -v`.
Supported audit/CI runtime: Python 3.11.
